## 1. Local Endpoint Evidence

On Unix, the local endpoint resolver opens each absolute-path directory component relative to a pinned parent with no-follow flags. It checks each opened directory against its parent-relative observation, retains the ancestor handles, and validates the final device and inode against the configured stable identity. Revalidation checks that every pinned component is still reachable through the same parent and that an available Linux mount identity remains unchanged. `fstatvfs` provides checked capacity and available-byte observations. These observations can change immediately and do not reserve space.

Scope evidence is emitted only after checking all supplied endpoints together. Ancestor and identical-directory overlaps are rejected. If endpoint mount identities are missing or differ, the resolver reports an ambiguous scope rather than asserting disjointness, because mount aliases can hide physical ancestry. This means macOS currently cannot establish a disjoint pair through this helper. Linux mount IDs are used when available, but later mount or path changes still require revalidation at admission. This helper does not supply grants, capabilities, encryption, or an authorization decision.

Each endpoint pins at most 129 directory descriptors. A scope-evidence call accepts at most 128 endpoints and 1,024 pinned descriptors in total. Its memory use is bounded by these counts and path component sizes; filesystem and kernel descriptor costs are separate. It does not hold source content in memory. The resolver rejects symlink path components, so callers must provide a path without symlink ancestors. Windows reports an explicit unsupported result.
