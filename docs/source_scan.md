## 1. Best-Effort Source Scanner

The Linux and macOS scanner walks a directory through pinned file descriptors and streams entries into a caller-supplied manifest spool. It uses no-follow opens, compares each opened entry with its parent-relative observation, hashes regular files in 64 KiB blocks, and rechecks file and directory identity, size, modification time, and change time. It checks the root path again after traversal. Linux pins regular-file candidates with `O_PATH` and opens their verified inodes through `/proc/self/fd`, preventing a replaced source name from opening a device as a content stream. Linux execution therefore requires a trusted mounted procfs. Directory names use lossless Unix bytes accepted by the underlying filesystem. Metadata is currently empty, and symbolic links, special files, and entries on another device are rejected.

The caller supplies finite depth, descriptor, entry, per-file, and total-byte limits. Cancellation and monotonic deadlines are checked between operations and reads. The scanner consumes its spool and returns it only on success; after an error the caller must discard the partial spool and must not publish it. The caller supplies a private spool outside the selected source and owns its cleanup. A successful returned spool can include entries the caller added previously and must be finalized separately.

This is a best-effort live read, not a snapshot or evidence that content remains immutable after it was checked. Metadata comparisons cannot detect every concurrent mutation. Some filesystems may block individual filesystem operations despite nonblocking flags, so deadline checks cannot guarantee a hard syscall deadline. Device-number checks do not detect same-device bind mounts. The scanner does not preserve links or metadata, allocate resource-pool permits, provide staging, or implement capture publication. The caller must reserve scanner resources and supply policy, capability, and authorization checks before use. Windows and other unsupported targets return an explicit unsupported error.

The initial root path must already be resolved and authorized by the caller; no-follow flags protect its last component and subsequent descriptor-relative descent. The macOS implementation can detect a raced replacement after an entry is opened, but cannot prevent a device node from being opened before its type is checked. An untrusted mutable macOS source requires additional access isolation before admission. This component is unavailable to enabled jobs until the remaining preflight and isolation requirements are implemented.
