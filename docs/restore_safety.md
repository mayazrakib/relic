## 1. Scope

The Unix regular-file primitive accepts one raw native name and an already open destination directory handle. It rejects empty names, separators, NUL, `.` and `..`, while retaining non-UTF-8 bytes. A separate helper opens or creates up to 32 components relative to a pinned root, without following symlinks, and holds only the current and next traversal handles. It rejects directories on another device; same-device bind mounts are not detected. A caller must validate the manifest base64url representation and pin the intended root. Windows and other non-Unix targets return an unsupported result.

The primitive streams through a 64 KiB buffer into a file in a pinned, owner-validated 0700 sibling directory with an explicit spool limit. It verifies exact length and SHA-256, synchronizes the file, creates the final name with no replacement, removes staging, and synchronizes the directory. It rejects an existing target, including a symlink. Cancellation is checked between reads and before publication; a blocking source read or filesystem call is not interruptible by this interface.

## 2. Authority and Durability Limits

The pinned private staging directory prevents replacement of its parent name from redirecting the source of publication. Mode 0700 does not isolate another process with the same user identity, which could mutate the staged file directly. The caller must hold exclusive mutation authority against such processes, and must prevent replacement of the staging directory name during cleanup. The destination handle identifies the directory object even if renamed; callers must also ensure its association with the planned destination remains valid. These prerequisites are not enforced by this primitive.

The operation does not preserve metadata, establish an archive restore plan, authorize overwrites, prove root identity, or report per-file progress. Concurrent directory renames can move an already opened directory outside its previous namespace, so the caller must prevent conflicting mutations during traversal and publication. Created directories can remain after an error or cancellation. The primitive does not prove safe extraction from an engine, crash cleanup, Windows reparse handling, or filesystem-specific durability. A failure after the final link is created returns an unknown outcome; callers must reconcile the target before retrying. Cleanup failure is reported separately. Rust `unsafe` calls are limited to descriptor-relative POSIX operations and transferring ownership of a newly opened descriptor.
